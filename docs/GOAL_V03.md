# CFD Assistant v0.3 实施任务书

版本：v0.3 planning  
日期：2026-06-18  
适用范围：CFD Assistant 前端网页应用、参数计算模块、公式研究与实现、Fluent 功能导览、UI/UX、研究记录、测试与本地 Git 里程碑。

## 1. 当前基线

v0.3 基于 v0.2 成果继续推进。当前项目已经具备：

- React + TypeScript + Vite + React Router + Vitest + PWA 基础结构。
- 参数计算三级结构：分类首页 -> 分类详情页 -> 单个计算器详情页。
- 已实现一批定义清楚的计算器：Reynolds、Mach、Prandtl、Peclet、Grashof、Rayleigh、Fourier、Biot、水力直径、CFL 时间步长、边界层网格等比增长。
- 已接入 KaTeX 公式渲染，支持复制 LaTeX、结果和计算摘要。
- Fluent 导览已有功能树、教学面板、解释面板、搜索、关联功能和关联计算器跳转。
- 研究记录目录已建立：
  - `docs/research/calculators/`
  - `docs/research/fluent/`

v0.3 的目标不是重新推翻 v0.2，而是在现有分层和技术路线基础上，把项目推进为更完整、更接近可公开发布的专业网页应用。

## 2. v0.3 总目标

v0.3 需要完成以下方向：

- 优化首页封面主视觉，使其真正表达 CFD Assistant 的产品内容。
- 继续扩展参数计算模块，增加更多来源明确、验证充分、可正式使用的计算器。
- 强化公式展示与计算实现的一致性，保证页面公式、LaTeX、纯函数实现、测试案例和研究记录互相对应。
- 将 Fluent 导览从当前 MVP 推进为更有教学意义的高保真模拟界面。
- 继续维护研究记录、状态管理、路线图、架构说明、决策记录和变更记录。
- 保持纯前端静态应用路线，不新增后端、不连接数据库、不接入外部 API、不做 AI 问答。
- 所有公开页面保持专业、清楚、有设计感，不显示开发 TODO、内部审核状态或研究备注。

## 3. 全局执行规则

- 只在当前项目目录内修改：`C:\Users\Administrator\Desktop\cfd-assistant`。
- 不推送 GitHub。
- 不部署 Cloudflare Pages。
- 不写入密码、令牌、验证码、账号凭据。
- 不要求用户在聊天中提供 GitHub 密码、验证码或访问令牌。
- 不使用 Ansys 或 Fluent 官方 Logo。
- 不复制官方截图、官方图标或逐像素复刻官方视觉设计。
- 不大段复制官方帮助文档；用户可见解释必须使用自己的语言准确概括。
- 不把专业猜测包装成确定结论。
- 证据不足的公式或经验关联式不得作为正式可用功能公开。
- 每个稳定阶段创建本地 Git 提交，提交信息必须清楚描述阶段成果。
- 每个代码阶段必须运行：

```powershell
npm.cmd run lint
npm.cmd run test
npm.cmd run build
```

- 测试、lint 或生产构建失败时，必须修复，不得声称完成。
- 浏览器冒烟测试必须确认控制台无应用级 error。
- 工作受阻时先记录阻塞原因，再继续其他独立任务。
- 只有登录、验证码、Token、管理员权限、项目目录外修改、不可逆操作、权威来源实质冲突时才暂停等待用户。

## 4. 首页封面优化

### 4.1 问题

当前首页左侧主视觉仍偏通用浏览器插画，和 CFD Assistant 的核心价值关联不够强。v0.3 需要重新设计首页主视觉，使用户第一眼能理解这是一个 CFD 工程计算和 Fluent 学习辅助工具。

### 4.2 新主视觉方向

新的主视觉应体现以下内容中的至少三项：

- CFD 参数计算。
- 公式与结果展示。
- 单位选择与输入输出表单。
- Fluent 功能学习导览。
- 工程工作台或技术工具界面感。
- 功能树、设置面板、解释面板三栏教学逻辑。

### 4.3 实现规则

- 优先采用自主设计的 SVG / CSS illustration / 组件化插图。
- 不继续使用抽象但缺乏含义的通用浏览器窗口插画。
- 可以预留 `src/assets` 或等价资源结构，用于后续替换为 GPT image 生成插图。
- 不使用 Ansys 或 Fluent 官方 Logo、截图、图标或视觉复刻。
- 首页整体仍保持简洁、现代、专业、有设计感，不加入花哨动画。
- 移动端主视觉必须可缩放、可读、不卡顿，不遮挡主操作入口。

### 4.4 验收标准

- 首页首屏能同时传达“计算器”和“学习导览”两个核心功能。
- 主视觉不再像通用模板插画。
- 桌面和手机端都不溢出、不裁切关键信息。
- 页面无乱码、无公开 TODO、无开发说明。

## 5. 参数计算模块继续完善

### 5.1 信息架构

继续保持三级结构：

```text
参数计算分类首页
  -> 分类详情页
    -> 单个计算器详情页
```

分类继续包括：

- 近壁面与网格
- 瞬态与时间步长
- 无量纲数
- 流动与管路
- 传热与热工

### 5.2 正式计算器要求

每个正式计算器页面必须显示：

- 输入项
- 单位选择
- 输入校验
- 计算按钮
- 重置按钮
- 输出结果
- 中间结果
- 计算所用公式
- 变量定义
- 单位说明
- 适用范围
- 注意事项
- 参考来源
- 更新时间
- 复制公式 LaTeX
- 复制结果
- 复制完整计算摘要

### 5.3 公式一致性要求

每个已正式实现的计算器必须保证以下内容一致：

- 研究记录中的公式。
- `src/calculators` 中的实际计算逻辑。
- `src/calculators/registry.ts` 或后续数据文件中的展示公式。
- 页面渲染出的 KaTeX 公式。
- 原始 LaTeX 字符串。
- 测试中的验证案例。
- 用户复制出的计算摘要。

如果公式有分支条件，分支条件必须在研究记录、代码和页面说明中同时存在，不得隐式选择。

### 5.4 公式来源规则

Codex 需要自行检索相关公式、输入参数、输出参数、符号定义、单位、适用范围和验证案例。来源优先级：

1. 正式标准。
2. 权威教材。
3. 官方理论指南。
4. 同行评审论文。
5. 大学或国家实验室资料。

不得只根据博客、论坛、问答网站、百科片段或搜索摘要实现公式。

经验关联式应尽量使用两个独立权威来源交叉验证。若来源之间存在系数、符号、适用范围或单位差异，必须记录差异，并暂停公开实现该分支。

### 5.5 优先实现范围

继续优先完善定义清楚、容易验证的计算器：

- Reynolds 数
- Mach 数
- Prandtl 数
- Peclet 数
- Grashof 数
- Rayleigh 数
- Fourier 数
- Biot 数
- 水力直径
- CFL 与时间步长
- 边界层网格等比增长

v0.3 可进一步增加但必须先研究验证的候选项：

- 旋转机械时间步长。
- 管道压降的基础 Darcy-Weisbach 形式。
- 矩形通道、环形通道等水力直径快捷几何。
- 理想气体声速辅助输入。
- Peclet 数的质量扩散形式。
- Rayleigh / Grashof 的几何与边界条件说明增强。

### 5.6 y+ 专项规则

y+ 与第一层网格高度属于复杂计算器，不得草率公开。

必须额外研究并记录：

- 内流 / 外流。
- Darcy / Fanning 摩阻系数。
- 局部 / 平均摩擦系数。
- 层流 / 湍流 / 转捩。
- 第一层中心距离 / 第一层完整厚度。
- 平板、管内流、外部绕流等场景差异。
- 壁面函数、低 Reynolds 模型和近壁解析网格要求。

如果上述问题未验证清楚：

- 只保留页面结构、输入草案、安全空状态和研究记录。
- 不公开自动计算结果。
- 不显示“内部待审核”或 TODO 给普通用户。

## 6. 公式研究记录与状态管理

### 6.1 计算器研究记录

计算器研究记录放在：

```text
docs/research/calculators/
```

每个正式计算器必须有独立研究记录，至少包含：

- 计算器 ID。
- 公式名称。
- 公式来源。
- 文档名称。
- 章节或页码。
- 链接。
- 访问日期。
- 原始公式。
- 原始 LaTeX。
- 变量定义。
- SI 单位。
- 输入参数。
- 输出结果。
- 中间量。
- 适用范围。
- 假设条件。
- 分支条件。
- 验证案例。
- 误差容差。
- 审核状态。
- 尚未解决的问题。

### 6.2 状态定义

建议使用以下状态管理计算器：

- `research-only`：仅有研究记录或页面结构，不公开计算。
- `draft-calculation`：已有计算函数，但仍不作为正式公开功能。
- `source-checked`：来源已核对，公式和变量清楚。
- `formula-reviewed`：公式、单位、分支和验证案例已审核。
- `published`：可在公开页面作为正式计算器展示。

公开页面只能将 `formula-reviewed` 或 `published` 的内容作为正式功能展示。其他状态只能使用产品化空状态，不显示内部状态名。

### 6.3 文档维护

v0.3 实施过程中需要持续维护：

- `CHANGELOG.md`
- `docs/research/calculators/`
- `docs/research/fluent/`

需要记录：

- 哪些计算器已经验证。
- 哪些计算器仍未验证。
- 哪些公式分支被暂停。
- 哪些 Fluent 条目已完成。

## 7. Fluent 功能导览重做

### 7.1 当前问题

当前 Fluent 导览已经有功能树、教学面板和解释面板，但教学意义仍不够强。v0.3 需要让导览界面更接近 Fluent 的真实使用逻辑和操作节奏，同时保持自主设计和知识产权边界。

### 7.2 高保真教学模拟界面目标

导览界面应具备：

- 左侧功能树 / 工作流目录。
- 中间主工作区 / 设置页 / Task Page 风格区域。
- 右侧解释面板。
- 可点击的参数项、下拉框、复选框、按钮、标签页。
- 某些按钮点击后打开新的教学模拟窗口。
- 新窗口中的控件也可以继续点击。
- 点击任何可解释控件后，右侧立即显示该控件的意义、用途、适用场景、影响和注意事项。
- 搜索功能。
- 关联功能跳转。
- 关联计算器跳转。

### 7.3 合规边界

- 不连接 Fluent。
- 不执行真实仿真。
- 不使用官方 Logo。
- 不复制官方截图。
- 不复制官方图标。
- 不逐像素复刻官方视觉设计。
- 可以模拟学习逻辑、工作流结构和操作层级。
- 所有用户可见解释必须用自己的语言概括。

### 7.4 知识库驱动规则

所有解释内容必须来自知识库，不得硬编码在组件中。

组件只能负责：

- 渲染布局。
- 根据条目 ID 切换内容。
- 根据结构化控件数据渲染控件。
- 根据控件 ID 显示解释。
- 打开或关闭模拟窗口。
- 执行搜索和跳转。

知识库应负责：

- 功能树节点。
- Task Page 面板结构。
- 控件 ID。
- 控件类型。
- 控件标签。
- 控件默认展示值。
- 控件解释。
- 对话框结构。
- 对话框内部控件。
- 关联功能。
- 关联计算器。
- 来源和版本信息。

### 7.5 必须实现的交互路径

v0.3 最终至少要有一条完整交互路径：

```text
功能树
  -> 设置页
    -> 点击控件
      -> 右侧解释
        -> 打开模拟窗口
          -> 点击窗口控件
            -> 显示窗口控件解释
```

示例路径可以从以下场景中选择：

- Boundary Conditions -> Velocity Inlet -> Turbulence 按钮 -> 模拟入口湍流设置窗口。
- Boundary Conditions -> Wall -> Thermal / Roughness 按钮 -> 模拟壁面热边界或粗糙度窗口。
- Solution Methods -> SIMPLE -> Under-Relaxation Factors 按钮 -> 模拟松弛因子窗口。
- Initialization -> Hybrid Initialization -> Initialize 按钮 -> 模拟初始化过程设置窗口。

## 11. 阶段顺序

### Stage 0：v0.3 任务书与状态盘点

目标：

- 创建 `docs/GOAL_V03.md`。
- 明确 v0.3 范围、阶段、验收标准和执行规则。
- 盘点当前已实现计算器、Fluent 条目和研究记录状态。

验收：

- `docs/GOAL_V03.md` 存在且覆盖本任务书要求。
- 本阶段不大规模修改业务代码。

### Stage 1：首页主视觉重设计

目标：

- 替换当前通用浏览器插画。
- 设计能表达 CFD 参数计算、公式结果展示和 Fluent 学习导览的工程工具主视觉。

验收：

## 12. v0.3 完成标准

v0.3 完成时必须满足：

- 首页主视觉已优化，并能表达 CFD 参数计算、公式结果展示和 Fluent 学习导览。
- 参数计算模块保持三级结构。
- 参数计算模块扩展一批正式计算器或正式分支。
- 每个正式计算器可展示正确公式、变量、单位、适用范围、注意事项和来源。
- 每个正式计算器支持复制 LaTeX、复制结果和复制完整计算摘要。
- 公式实现逻辑、展示公式和 LaTeX 保持一致。
- y+ 未完全验证前不公开不可靠自动计算。
- Fluent 教学模拟界面比当前更接近真实使用逻辑。
- 至少有一条完整 Fluent 交互路径支持：
  功能树 -> 设置页 -> 点击控件 -> 右侧解释 -> 打开模拟窗口 -> 点击窗口控件 -> 显示解释。
- 所有公开内容来源于数据和知识库，不硬编码在页面组件中。
- `docs/research/calculators` 和 `docs/research/fluent` 持续维护。
- `ROADMAP`、`CHANGELOG`、`ARCHITECTURE`、`DECISIONS` 反映当前状态。
- 公开页面不显示开发 TODO、研究备注、内部审核状态或源码路径。
- 手机和电脑端都可正常阅读和操作。
- lint、test、build 全部通过。
- 浏览器控制台无应用级 error。
- 本地开发服务器可启动，并提供浏览器访问链接。

## 13. v0.3 不包含的事项

除非用户另行明确要求，v0.3 不做：

- GitHub 推送。
- Cloudflare Pages 部署。
- Android App 封装。
- 后端服务。
- 数据库。
- 用户登录。
- 会员、支付或账号系统。
- AI 问答。
- 多相流、燃烧、辐射、动网格、离散相的完整覆盖。
- 未经权威来源验证的经验关联式公开计算。
