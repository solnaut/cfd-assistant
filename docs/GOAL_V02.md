# CFD Assistant v0.2 实施任务书

版本：v0.2 planning  
日期：2026-06-18  
适用范围：CFD Assistant 前端网页应用、参数计算模块、Fluent 功能导览模块、研究记录与验证流程。

## 1. 任务目标

v0.2 的目标是把 CFD Assistant 从“可运行骨架”推进为“可持续实现真实内容的专业网页应用基础版本”。本阶段优先完成：

- 优化网站整体 UI，使其简洁、现代、专业，适配手机和电脑。
- 重构并稳定“参数计算”的信息架构与交互方式。
- 为首批定义清楚、来源明确的计算器建立研究记录、公式实现、测试和展示规范。
- 建立 Fluent 功能导览的高保真教学模拟界面和知识库驱动机制。
- 保持纯前端静态应用路线，不创建后端、不连接数据库、不接入外部 API、不实现 AI 问答。

公开页面不得显示面向开发过程的内容，包括但不限于内部审核状态、未完成标记、公式研究备注、源码路径、实现规则、调试信息或开发说明。

## 2. 全局工作规则

- 只在当前项目目录内工作：`C:\Users\Administrator\Desktop\cfd-assistant`。
- 不把密码、令牌、验证码、账号凭据写入代码、文档或提交记录。
- 不要求用户在聊天中提供 GitHub 密码、验证码或访问令牌。
- 不使用 Ansys 或 Fluent 官方 Logo。
- 不复制官方截图、官方图标或逐像素复刻官方视觉设计。
- 不直接大段复制官方帮助文档；所有面向用户的解释必须用自己的语言概括。
- 不把专业猜测伪装成确定结论。
- 证据不足时，只建立页面结构、研究记录和内部占位，不公开不可靠计算。
- 工作受阻时先记录阻塞原因，再继续其他独立任务。
- 只有以下情况暂停并等待用户：登录、验证码、Token、管理员权限、项目目录外修改、不可逆操作、权威来源之间存在实质冲突。

## 3. UI/UX 改版要求

### 3.1 视觉方向

- 简洁、现代、专业，偏工程工具和技术产品风格。
- 页面层级清晰，留白充足，卡片、按钮、导航和标题区视觉一致。
- 中英文混排保持清楚、紧凑、可读。
- 桌面端优先提供高效信息密度，移动端优先保证阅读和操作舒适。
- 可使用本地 SVG、简洁图标或抽象插图，但必须避免官方品牌资产。
- 预留后续替换为更高级插图或生成式图片资源的目录和组件边界。

### 3.2 页面内容规则

公开页面不得显示：

- `TODO`、内部审核状态或开发过程说明。
- “等待审核”“公式未确认”“数据定义边界”等内部维护语气。
- 源码路径、测试说明、实现规则或项目治理说明。
- 只适合写在 docs 或代码注释中的维护提示。

如果需要提示某个功能尚未完整开放，应使用产品化空状态，例如：

- “该计算器正在完善中。”
- “输入项与结果展示结构已预留。”
- “完整计算逻辑与工程说明将在后续版本补充。”

## 4. 参数计算模块信息架构

参数计算必须采用三级结构：

```text
参数计算分类首页
  -> 分类详情页
    -> 单个计算器详情页
```

### 4.1 分类首页

分类首页只展示计算器分类，不直接平铺所有计算器。分类包括：

- 近壁面与网格
- 瞬态与时间步长
- 无量纲数
- 流动与管路
- 传热与热工

每个分类卡片至少包含：

- 分类名称
- 一句话说明
- 简洁图标或抽象视觉元素
- 分类下工具数量
- 进入分类的可点击区域

### 4.2 分类详情页

分类详情页展示该分类下的计算器列表。每个计算器条目至少包含：

- 名称
- 一句话功能说明
- 输入项数量或简短摘要
- 进入按钮

分类与计算器建议映射：

| 分类 | 计算器 |
| --- | --- |
| 近壁面与网格 | y+ 与第一层网格高度、边界层网格等比增长 |
| 瞬态与时间步长 | CFL 与时间步长、旋转机械时间步长 |
| 无量纲数 | Reynolds、Mach、Prandtl、Peclet、Grashof、Rayleigh、Fourier、Biot |
| 流动与管路 | 水力直径、管道压降 |
| 传热与热工 | 传热相关无量纲数与热工参数整理 |

### 4.3 单个计算器详情页

正式计算器页面必须包含：

- 页面标题
- 简要功能说明
- 输入区
- 单位选择
- 输入校验
- 计算按钮
- 重置按钮
- 结果区
- 中间结果区
- 公式说明
- 变量说明
- 适用范围
- 工程注意事项
- 来源
- 更新时间
- 复制 LaTeX
- 复制结果
- 复制完整计算摘要

公式必须使用 KaTeX 或同等级规范数学排版，同时保存原始 LaTeX 字符串。

## 5. 优先实现的计算器

优先研究并实现定义清楚、可验证、来源明确的计算器：

1. Reynolds 数
2. Mach 数
3. Prandtl 数
4. Peclet 数
5. Grashof 数
6. Rayleigh 数
7. Fourier 数
8. Biot 数
9. 水力直径
10. CFL 与时间步长
11. 边界层网格等比增长

以上计算器的实现顺序以“公式定义清楚、输入输出简单、验证数据容易取得”为优先原则。建议先做无量纲数和水力直径，再做 CFL、边界层网格和 y+。

## 6. 公式研究与来源规则

Codex 需要自行检索资料，但必须遵守来源优先级。

### 6.1 来源优先级

1. 正式标准
2. 权威教材
3. 官方理论指南
4. 同行评审论文
5. 大学或国家实验室资料

不得仅根据博客、论坛、问答网站、百科片段、搜索结果摘要或未经核验的网页实现公式。

经验关联式应尽量使用两个独立权威来源核对。若两个来源存在符号、单位、系数或适用范围差异，必须记录差异，不得直接合并为一个确定结论。

### 6.2 每个公式必须记录的信息

每个公式研究记录必须包含：

- 计算器 ID
- 公式名称
- 公式来源
- 章节或页码
- 链接
- 访问日期
- 原始公式
- 原始 LaTeX
- 变量定义
- SI 单位
- 输入参数
- 输出结果
- 适用范围
- 假设条件
- 分支条件
- 验证案例
- 误差容差
- 审核状态
- 尚未解决的问题

研究记录存放目录：

```text
docs/research/calculators/
```

每个计算器建议单独建立一个 Markdown 文件，例如：

```text
docs/research/calculators/reynolds-number.md
docs/research/calculators/cfl-time-step.md
```

## 7. y+ 专项规则

y+ 与第一层网格高度属于多关联式、多假设、多工程分支问题，不能直接按单一经验式实现。

研究必须覆盖：

- 外流与内流差异
- 局部摩擦系数与平均摩擦系数差异
- Darcy 摩阻系数与 Fanning 摩阻系数差异
- 层流与湍流差异
- 平板、管内流、外部绕流等不同场景
- 第一层单元中心距离与完整第一层厚度的差异
- 壁面函数、低 Reynolds 模型和近壁解析网格的不同要求
- 输入参数对摩擦速度、壁面剪切应力和第一层高度的影响

若证据不足或分支条件无法清楚界定，只建立：

- 页面结构
- 输入输出草案
- 研究记录
- 用户可见的安全空状态

不得公开不可靠的 y+ 自动计算结果。

## 8. 计算实现架构

### 8.1 分层要求

计算逻辑、单位换算、页面和数据必须分离：

- 页面组件：负责布局、输入、校验反馈、操作和展示。
- 计算模块：负责纯函数计算，不依赖 DOM。
- 单位模块：负责单位定义、换算和 SI 归一化。
- 数据模型：负责计算器元数据、公式元数据、验证案例和展示配置。
- 知识库：负责 Fluent 导览内容，不写在组件里。

### 8.2 单位与数值规则

- 内部统一使用 SI 单位计算。
- 输入值必须先完成单位换算，再进入计算函数。
- 输出值可以按用户选择单位展示。
- 必须防止除零、`NaN` 和 `Infinity`。
- 非法输入必须给出清晰校验反馈，不能静默失败。
- 分支公式必须显式记录条件，不能隐式选择。

### 8.3 测试要求

每个正式计算器必须至少包含：

- 正常案例测试
- 单位换算案例测试
- 边界案例测试
- 非法输入测试
- 来源验证案例测试

测试必须覆盖计算函数和单位换算，不只覆盖页面渲染。

## 9. Fluent 功能导览目标

Fluent 功能导览采用自主设计的高保真教学模拟界面：

- 不连接 Fluent。
- 不执行真实仿真。
- 不复制官方 Logo、截图、图标或逐像素视觉设计。
- 使用与 Fluent 工作流相近的功能分类和交互逻辑。
- 所有解释内容由知识库 ID 驱动，不在组件中硬编码。

### 9.1 Fluent 资料来源

Fluent 资料优先使用公开可访问的：

- Ansys Fluent User's Guide
- Ansys Fluent Theory Guide
- Ansys Release Notes
- Ansys 官方教程

可补充使用大学课程资料、国家实验室资料和同行评审论文。所有内容必须用自己的语言概括。

研究记录存放目录：

```text
docs/research/fluent/
```

每条研究记录必须包含：

- Fluent 版本
- 资料标题
- 章节
- 链接
- 访问日期
- 摘要
- 适用功能节点
- 需要进一步确认的问题

### 9.2 Fluent 导览交互结构

正式导览界面应包含：

- 左侧功能树
- 中间教学设置面板
- 右侧解释面板
- 点击节点切换中间面板和右侧解释
- 点击按钮、下拉项、复选框等控件显示解释
- 部分按钮打开模拟对话框
- 对话框内部选项也可点击解释
- 搜索
- 相关功能跳转
- 相关计算器跳转

所有控件、面板、对话框和解释必须由知识库 ID 驱动。组件只能根据 ID 和结构化数据渲染界面，不能硬编码具体知识正文。

### 9.3 第一阶段覆盖范围

第一阶段覆盖常用单相流动和传热功能：

- General
- Models
- Materials
- Cell Zone Conditions
- Boundary Conditions
- Solution Methods
- Initialization
- Monitors
- Run Calculation
- Results

后续待办范围：

- 多相流
- 燃烧
- 辐射
- 动网格
- 复杂物理模型和高级求解控制

### 9.4 Fluent 知识条目字段

Fluent 知识条目必须包含：

- `id`
- `parentId`
- `controlType`
- 英文名称
- 中文名称
- 路径
- 功能说明
- 使用场景
- 选项区别
- 前置条件
- 对精度、稳定性和计算成本的影响
- 常见错误
- 检查建议
- 关联功能
- 关联计算器
- 版本
- 来源
- 更新时间
- 审核状态

## 10. 质量门禁

每个稳定阶段必须运行：

```powershell
npm.cmd run lint
npm.cmd run test
npm.cmd run build
```

并进行浏览器冒烟测试：

- 首页可打开。
- 参数计算分类首页可打开。
- 至少一个分类详情页可打开。
- 至少一个计算器详情页可打开。
- Fluent 功能导览可打开。
- 浏览器控制台无 error 级错误。
- 公开页面正文不显示内部未完成标记、内部审核状态或开发过程说明。

测试失败必须修复，不得声称任务完成。

## 11. Git、部署与本地运行规则

- 每个稳定阶段创建本地 Git 提交。
- 提交信息必须清楚描述阶段成果。
- v0.2 实施过程中默认不推送 GitHub，除非用户明确要求。
- v0.2 实施过程中默认不部署 Cloudflare Pages，除非用户明确要求。
- 每个阶段结束时启动本地开发服务器并提供浏览器访问链接。
- PowerShell 中优先使用 `npm.cmd`。

## 12. 阶段顺序

### Stage 1：UI 与信息架构稳定

目标：

- 首页产品化。
- 参数计算形成分类首页、分类详情、计算器详情三级结构。
- Fluent 导览视觉与整体风格统一。
- 公开页面不显示内部开发说明。

验收：

- `/`
- `/calculators`
- `/calculators/near-wall-mesh`
- `/calculators/near-wall-mesh/y-plus-first-layer-height`
- `/fluent-guide`

均可打开，移动端和桌面端布局可读。

### Stage 2：研究记录模板与目录

目标：

- 建立 `docs/research/calculators/`。
- 建立 `docs/research/fluent/`。
- 建立计算器研究记录模板。
- 建立 Fluent 研究记录模板。

验收：

- 每个模板字段完整覆盖来源、访问日期、变量、单位、适用范围、验证案例和审核状态。

### Stage 3：首批简单计算器实现

候选顺序：

1. Reynolds
2. Mach
3. Prandtl
4. Peclet
5. Fourier
6. Biot
7. Grashof
8. Rayleigh
9. 水力直径

目标：

- 每个计算器先完成研究记录。
- 来源符合优先级。
- 计算函数独立。
- 单位换算独立。
- 页面展示完整。
- 测试覆盖正常、单位、边界、非法输入和验证案例。

### Stage 4：CFL、边界层网格与复杂分支

目标：

- 实现 CFL 与时间步长。
- 实现边界层网格等比增长。
- 对分支条件、假设和限制进行清晰展示。

### Stage 5：y+ 研究与保守实现

目标：

- 完成 y+ 专项研究记录。
- 明确哪些场景可以可靠计算。
- 不可靠场景只提供说明和输入结构，不给出自动结果。

### Stage 6：Fluent 导览 MVP

目标：

- 建立可扩展的功能树数据结构。
- 建立教学设置面板渲染结构。
- 建立右侧解释面板。
- 支持搜索、相关功能跳转和相关计算器跳转。
- 第一阶段覆盖常用单相流动和传热功能。

## 13. 完成标准

v0.2 可认为完成时必须满足：

- 首页和核心模块页面达到准备发布的视觉质量。
- 参数计算三级结构稳定。
- 至少一批定义清楚的计算器具备研究记录、公式实现、单位换算、页面展示和测试。
- 每个正式计算器都有来源、变量、单位、适用范围、验证案例和更新时间。
- Fluent 导览由知识库 ID 驱动，不硬编码知识正文。
- Fluent 导览具备功能树、教学面板、解释面板和基础搜索。
- 公开页面不显示内部未完成标记、审核状态或开发说明。
- lint、test、production build 和浏览器冒烟测试全部通过。
- 每个稳定阶段有本地 Git 提交。
- 本地开发服务器可启动，并提供可访问的本地浏览器链接。
