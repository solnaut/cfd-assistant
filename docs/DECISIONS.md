# Decisions

## ADR-0001: 使用 React + TypeScript + Vite

日期：2026-06-18

选择 React、TypeScript 和 Vite 作为第一阶段技术栈。原因是开发体验成熟、静态构建简单、适合 Cloudflare Pages，也便于后续通过 Capacitor 封装移动应用。

## ADR-0002: 第一阶段不创建后端

日期：2026-06-18

第一阶段所有计算和知识读取都在浏览器本地完成。不创建后端服务器、不连接数据库、不做登录、会员或支付。这降低部署和维护复杂度。

## ADR-0003: 知识内容使用本地 JSON

日期：2026-06-18

Fluent 导览内容存放在 `public/knowledge`。页面通过知识条目 ID 读取内容，避免把解释写死在组件中。后续如果内容规模变大，可迁移到构建期生成的索引或轻量搜索索引。

## ADR-0004: 未审核专业内容必须 TODO

日期：2026-06-18

CFD 公式、经验关联式、适用范围和工程建议必须由用户提供或审核。未确认前只能以 TODO 占位，避免把猜测伪装成确定结论。

## ADR-0005: PWA 先做基础预留

日期：2026-06-18

第一阶段加入 PWA 基础配置，但不把离线能力作为核心验收项。这样可以为移动端安装体验和后续 Android 封装保留路径。

## ADR-0006: 使用 KaTeX 渲染公式

日期：2026-06-18

正式计算器页面使用 KaTeX 渲染数学公式，同时保存原始 LaTeX 字符串。原因是工程计算器需要清晰、规范、可复制的公式表达，并且公式展示必须与计算逻辑和研究记录保持一致。

## ADR-0007: 复杂经验关联式先研究后公开

日期：2026-06-18

y+、摩阻因子经验关联式、自然对流换热关联式等多分支内容不得在证据不足时公开自动计算。此类内容先进入研究记录和安全空状态；只有来源、分支条件、单位、验证案例和审核状态齐全后，才作为正式计算器开放。

## ADR-0008: Fluent 模拟窗口由知识库驱动

日期：2026-06-18

Fluent 导览的模拟窗口、窗口标题、窗口说明和窗口内部控件全部放在结构化知识库中，由控件的 `dialog.controls` 描述。页面组件只负责渲染和状态切换。这样后续扩展按钮、下拉项、复选框和模拟对话框解释时，不需要改写页面组件，也能避免把专业说明硬编码在代码中。

## ADR-0009: 公式库复用计算器公式定义

日期：2026-06-18

新增 CFD 公式库时，不创建独立公式数据副本，而是读取 `src/calculators/registry.ts` 中正式计算器的公式、变量和适用范围定义。这样可以避免计算器页面和公式库公式不一致。若后续公式规模变大，可在保持单一数据源原则的前提下拆分为 `src/calculators/formulas.ts` 或构建期生成数据。

## ADR-0010: 用户界面显示符号与内部单位 ID 分离

日期：2026-06-18

内部单位 ID 继续使用稳定 ASCII 字符串，便于代码、测试和单位换算维护；用户界面通过 `displaySymbol` 和显示格式化函数输出工程可读符号，例如 `μ`、`ρ`、`Pa·s`、`kg/m³`、`m²/s`。公式 LaTeX 保留反斜杠形式，仅用于 KaTeX 渲染和复制。

## ADR-0011: 来源记录保存在内部文档，公开页面不展示来源链接

日期：2026-06-18

计算器和 Fluent 条目的来源、访问日期、审核状态和验证依据保存在研究记录或结构化元数据中，但普通用户界面不显示外部来源链接列表。这样既保留专业可追溯性，又避免核心工具页面像开发审稿界面。维护者需要审查来源时，应查看 `docs/research/calculators`、`docs/research/fluent` 或对应数据文件。
